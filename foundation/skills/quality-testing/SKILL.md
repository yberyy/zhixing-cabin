# Quality Testing

按风险选择最小充分验证：

1. 运行 `npm test`，覆盖正常路径、非法输入、未知资源与持久化。
2. 涉及 UI 时启动 `npm run dev`，检查桌面与 390px 移动视口的首屏、导航、弹窗和主要操作。
3. 涉及离线逻辑时以静态服务器打开 `dist/`，确认 API 不可用时仍能新建与完成任务。
4. 涉及契约时对照 `shared/contracts/openapi.yaml` 检查状态码和响应形状。

只报告实际执行的检查。失败时保留可复现步骤，并将会影响交付的限制写入开发日志。
